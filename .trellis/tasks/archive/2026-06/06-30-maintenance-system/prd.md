# Maintenance 维护系统 - 产品需求文档 (PRD)

## 1. Goal 系统目的和价值

### 1.1 系统目的
Maintenance 维护系统是 Nocturne Memory 的大脑清理模块，负责识别、管理和清理系统中的"孤儿记忆"（orphaned memories）——这些记忆节点由于系统操作（如记忆更新、路径删除等）而失去可达性，但仍然占用存储空间。

### 1.2 核心价值
1. **存储优化**：清理不再可达的记忆节点，释放数据库空间
2. **系统健康**：提供系统运行状况的可视化，展示孤儿节点统计
3. **数据恢复**：允许用户恢复被意外隔离的重要记忆
4. **访问日志管理**：清理历史访问日志，维持系统性能
5. **安全删除**：提供可控的批量删除机制，避免误操作

### 1.3 与记忆节点系统的关系
- **上游依赖**：记忆节点系统的更新（`update_memory`）和路径删除操作会产生孤儿节点
- **下游影响**：清理操作永久删除数据，影响搜索索引和关联路径
- **隔离性**：孤儿节点在隔离状态（`deprecated=True`）下不参与正常业务逻辑

## 2. Requirements 功能需求列表

### 2.1 孤儿节点管理
- **R1**：列出所有孤儿节点，按类别（已弃用/完全孤儿）分组
- **R2**：显示每个孤儿节点的基本信息：ID、UUID、内容片段、创建时间
- **R3**：对于已弃用节点，显示迁移目标节点的路径信息
- **R4**：支持展开查看节点的完整内容和差异对比
- **R5**：支持单选和批量选择孤儿节点进行删除

### 2.2 孤儿节点恢复
- **R6**：允许恢复完全孤儿的节点（`category="orphaned"`）
- **R7**：提供路径选择器，支持域名（core/writer/project）和级联路径选择
- **R8**：恢复时支持设置优先级、披露条件（disclosure）、命名空间
- **R9**：恢复后激活节点（`deprecated=False`），重新建立路径关联

### 2.3 批量操作
- **R10**：支持按组选择（基于迁移目标分组）
- **R11**：支持全选/反选当前显示的所有节点
- **R12**：批量删除选中的孤儿节点，提供删除确认
- **R13**：批量删除支持部分失败处理，显示成功/失败统计

### 2.4 访问日志管理
- **R14**：显示全局访问日志统计（总数、最早记录时间）
- **R15**：支持清理访问日志，可选择保留天数（0=全部删除）
- **R16**：清理操作提供确认提示，防止误操作

### 2.5 用户体验
- **R17**：实时统计展示（已弃用/孤儿数量）
- **R18**：加载状态和错误处理
- **R19**：响应式布局，支持分组筛选视图
- **R20**：国际化支持（中英文）

## 3. API Specification 接口规范

### 3.1 孤儿节点相关接口

#### `GET /maintenance/orphans`
**描述**：获取所有孤儿记忆节点（`deprecated=True`）

**响应**：`200 OK`
```json
[
  {
    "id": 123,
    "node_uuid": "uuid-string",
    "content_snippet": "记忆内容片段...",
    "created_at": "2024-01-01T12:00:00",
    "deprecated": true,
    "migrated_to": 124, // 如果是已弃用版本，此为迁移目标ID
    "category": "deprecated", // "deprecated" 或 "orphaned"
    "migration_target": { // 仅当 migrated_to 存在时
      "id": 124,
      "paths": ["path/to/target"],
      "content_snippet": "目标内容片段..."
    }
  }
]
```

#### `GET /maintenance/orphans/{memory_id}`
**描述**：获取孤儿节点的完整详情，包含迁移目标的完整内容（用于差异对比）

**响应**：`200 OK`
```json
{
  "id": 123,
  "node_uuid": "uuid-string",
  "content": "完整的记忆内容",
  "created_at": "2024-01-01T12:00:00",
  "deprecated": true,
  "migrated_to": 124,
  "category": "deprecated",
  "migration_target": {
    "id":224,
    "content": "迁移目标的完整内容",
    "paths": ["path/to/target"],
    "created_at": "2024-01-02T12:00:00"
  }
}
```

**错误**：
- `404 Not Found`: 记忆不存在

#### `DELETE /maintenance/orphans/{memory_id}`
**描述**：永久删除一个孤儿记忆节点。如果该节点有版本链，会自动修复链条；如果是节点的最后一个记忆，会垃圾回收整个节点。

**响应**：`200 OK`
```json
{
  "deleted_memory_id": 123,
  "chain_repaired_to": 124, // 如果修复了版本链，指向新的后继ID
  "rows_before": {
    "nodes": [], // 如果整个节点被GC，这里会有节点数据快照
    "memories": [{...}], // 删除的记忆数据快照
    "edges": [],
    "paths": [],
    "glossary_keywords": []
  }
}
```

**错误**：
- `404 Not Found`: 记忆不存在
- `409 Conflict`: 尝试删除活跃记忆（安全保护）

#### `POST /maintenance/orphans/{memory_id}/restore`
**描述**：恢复一个孤儿记忆节点，为其分配新路径并激活

**请求体**：
```json
{
  "new_domain": "core", // 可选，默认"core"
  "new_path": "restored/path/name",
  "priority": 0, // 可选，默认0
  "disclosure": "触发条件", // 可选
  "namespace": "" // 可选，默认当前命名空间
}
```

**响应**：`200 OK`
```json
{
  "success": true,
  "memory_id": 123,
  "node_uuid": "uuid-string",
  "uri": "core://restored/path/name"
}
```

**错误**：
- `422 Unprocessable Entity`: 
  - 新路径为空
  - 父路径不存在
  - 路径已存在
  - 尝试恢复已弃用的历史版本（只能恢复完全孤儿节点）
  - 会创建循环依赖

### 3.2 访问日志相关接口

#### `GET /maintenance/access-logs/stats`
**描述**：获取访问日志的全局统计信息

**响应**：`200 OK`
```json
{
  "count": xtxxx, // 总记录数
  "oldest": "2024-01-01T12:00:00" // 最早记录时间，可能为null
}
```

#### `DELETE /maintenance/access-logs`
**描述**：清理访问日志。可指定保留天数，早于该天数的记录会被删除。

**请求体**：
```json
{
  "keep_days": 30 // 可选，null或0表示删除所有
}
```

**响应**：`200 OK`
```json
{
  "deleted": 1234 // 删除的记录数
}
```

### 4.2 交互流程

#### 4.2.1 查看孤儿节点
1. 页面加载时自动获取孤儿列表和日志统计
2. 按类别显示：已弃用版本(琥珀色) vs 完全孤儿(玫瑰色)
3. 点击记忆卡片可展开查看：
   - 完整记忆内容
   - 差异对比（如果有关联的迁移目标）
   - 恢复按钮（仅对完全孤儿节点）

#### 4.2.2 批量操作
1. **选择模式**：点击卡片左上角复选框选择单个记忆
2. **组选择**：点击侧边栏分组，选择/反选该组所有记忆
3. **批量删除**：选中记忆后，顶部显示"删除已选中"按钮
4. **确认删除**：弹出确认对话框，显示删除数量

#### 4.2.3 恢复孤儿节点
1. 点击完全孤儿节点的"恢复此记忆"按钮
2. 显示恢复配置表单：
   - 域名选择器（core/writer/project）
   - 级联路径选择器（基于浏览API动态加载子路径）
   - 新节点名称输入
   - 命名空间选择器（支持手动输入）
   - 披露条件和优先级设置
3. 提交后重新激活节点，更新搜索索引

#### 4.2.4 清理访问日志
1. 点击侧边栏底部的"清除"按钮
2. 弹出输入框："保留多少天的日志？"
3. 输入天数（0=全部删除，空值=默认30天）
4. 确认后异步执行清理，显示删除统计

## 5. Data Flow 数据流和生命周期

### 5.1 孤儿节点生命周期

```
创建活跃节点 → 更新操作 → 产生已弃用版本 → [路径删除] → 变为完全孤儿
    ↓              ↓              ↓                    ↓
正常访问     正常版本链    可通过迁移目标访问   不可访问，需恢复或删除
```

#### 5.1.1 已弃用版本（deprecated）的产生
```python
# update_memory 操作后
old_memory.deprecated = True
old_memory.migrated_to = new_memory.id
# old_memory 仍可通过 new_memory.paths 访问
```

#### 5.1.2 完全孤儿（orphaned）的产生
```python
# remove_path 操作后，如果节点失去所有路径
memory.deprecated = True
memory.migrated_to = None  # 无迁移目标
# memory 完全不可访问
```

### 5.2 清理操作数据流

#### 5.2.1 删除孤儿节点
```
DELETE /maintenance/orphans/{id}
  ↓
graph.permanently_delete_memory(id)
  ├── 检查是否为活跃节点（拒绝）
  ├── 修复版本链（如果 migrated_to 存在）
  ├── 删除记忆行
  └── 如果节点无其他记忆 → 垃圾回收整个节点
```

#### 5.2.2 恢复孤儿节点
```
POST /maintenance/orphans/{id}/restore
  ↓
graph.restore_orphan_memory(id, new_path, ...)
  ├── 验证新路径有效性（父路径存在，无重复）
  ├── 检查节点类型（拒绝恢复已弃用历史版本）
  ├── 检查循环依赖
  ├── 创建新路径关联
  ├── 激活记忆（deprecated=False）
  └── 刷新搜索索引
```

#### 5.2.3 清理访问日志
```
DELETE /maintenance/access-logs
  ↓
if keep_days > 0:
    cutoff = now() - timedelta(days=keep_days)
    delete logs where accessed_at < cutoff
else:
    delete all logs
```

### 5.3 分组逻辑

#### 5.3.1 分组算法
```javascript
// 前端分组逻辑（MaintenancePage.jsx）
1. 遍历所有孤儿节点
2. 已弃用节点（migrated_to 存在）按迁移目标ID分组
3. 孤儿节点（migrated_to 为null）尝试关联到相同UUID的已弃用组
4. 剩余的孤儿节点放入"孤儿"组
```

#### 5.3.2 分组数据结构
```json
{
  "key": "target:124", // 组唯一标识
  "type": "deprecated", // "deprecated" 或 "orphaned"
  "targetId": 124, // 迁移目标ID（仅deprecated组）
  "name": "迁移目标名称",
  "items": [...] // 组内记忆列表
}
```

## 8. Notes 备注

### 8.1 与记忆节点系统的关键关系
1. **孤儿产生机制**：
   - 更新记忆时，旧版本标记为 `deprecated=True`，`migrated_to` 指向新版本
   - 删除路径时，如果节点失去所有路径，标记为 `deprecated=True`，`migrated_to=None`

2. **恢复限制**：
   - 只能恢复 `migrated_to=None` 的完全孤儿节点
   - 历史版本（`migrated_to` 有值）不能恢复，因为其内容已被新版本替代

3. **删除安全**：
   - 活跃记忆（`deprecated=False`）永远不能被 Maintenance 系统删除
   - 删除操作会自动修复版本链，防止链条断裂

### 8.2 设计决策说明
1. **分组策略**：按迁移目标分组帮助用户理解哪些记忆属于同一更新链
2. **批量操作范围**：只对当前可见的记忆生效，防止误删隐藏项
3. **恢复流程**：要求完整路径选择，确保恢复后节点可达性
4. **日志清理**：提供保留天数选项，平衡存储和审计需求

### 8.3 未来扩展考虑
1. **自动清理策略**：可配置自动清理超过X天的孤儿节点
2. **批量恢复**：支持批量恢复孤儿节点到相同父路径
3. **统计报表**：生成清理报告，显示释放的存储空间
4. **备份机制**：删除前创建备份，支持误删恢复
5. **智能分组**：基于内容相似性自动分组孤儿节点

### 8.4 风险与缓解
1. **误删风险**：通过多重确认和部分失败处理缓解
2. **恢复冲突**：通过路径重复检查防止恢复冲突
3. **性能影响**：大规模清理时可能影响系统性能，需分批处理
4. **数据一致性**：删除和恢复操作需要维护版本链和搜索索引一致性
